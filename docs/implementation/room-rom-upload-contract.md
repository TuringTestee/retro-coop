Audience: Agent

# Private room game upload contract

A host first creates a hidden custom room through the existing WebSocket command, uploads the selected NES file through HTTP, and confirms the room only after the coordinator accepts the complete file. The coordinator keeps the verified bytes in a private temporary directory until that room closes. This is the RT1 server contract for RT2; the current client still uses the earlier local-file flow until RT2 connects it.

## Request and response

1. Send WebSocket `create` with the existing `intent`, `visibility`, and full `fingerprint`. Keep the selected `File` for retry. The returned room ID is a server-generated opaque ID; this pending room is absent from directory and invitation preview.
2. Send `PUT /rooms/{roomId}/rom` with `Authorization: Bearer {session.token}` from the host's WebSocket `hello`, `X-Room-Intent: {intent}` from `create`, and `Content-Type: application/octet-stream`. The browser supplies the exact allowed `Origin` and `Content-Length` for the original `File` body; application code must not try to set those restricted headers. Do not put the token or filename in the URL. Browser cross-origin preflight supports the client-set headers. Use an upload API that reports body progress and supports abort; the regular Fetch API does not provide portable upload progress.
3. HTTP `201` returns `{ "bytes": number, "sha256": string }` after the full stream is written, flushed, checked against the pending fingerprint's length and SHA-256, checked by the shared structural NES parser, and atomically committed. This response means `confirmCreate` may be sent. The browser still owns emulator core identity; the coordinator cannot derive it from the file.
4. HTTP failure returns JSON `{ "error": string }` and no committed file. Capacity and rate denial use HTTP 429, file-size denial 413, invalid session/host or origin 403, other expected validation errors 400, and unexpected server failure 500. Useful errors include `session_expired`, `host_only`, `room_changed`, `upload_unavailable`, `upload_size_limit`, `length_mismatch`, `hash_mismatch`, `invalid_cartridge`, `cartridge_mismatch`, and `upload_expired`. Retry can use the same intent before its five-minute total limit if the pending room still exists; after expiry, create a new hidden intent. Check the actual room state before retrying.
5. Send existing WebSocket `confirmCreate` with the same intent after HTTP 201. A custom room using this upload route cannot confirm while its bytes are uncommitted. `cancelCreate` or `leave` closes that exact pending room and removes its private bytes; abort the HTTP request as well. A later response cannot publish a cancelled or replacement intent.

`COORDINATOR_REQUIRE_CUSTOM_UPLOAD=1` enforces the commit barrier for every custom `create`, including clients that never attempt an upload. RT2 should enable this with its new host path and public demo together; this RT1 change leaves it off so the existing demo remains usable. Included-game `claimCode` rooms keep their existing asset path and do not upload. The server uses `COORDINATOR_ROM_DIR` when set, otherwise a private temporary directory. It is process exclusive, clears orphaned upload and blob files at startup, and removes current room files at closure or shutdown. Bounds are 64 MiB per file, 256 MiB total reserved or committed bytes, four concurrent uploads, five uploads per host and 30 HTTP attempts per address per minute, 30 seconds without progress, and five minutes total from room intent creation. A progressing upload keeps its pending room alive across the old five-second sweep.

RT3 can consume the committed private handle after adding current guest membership authorization and its own download lease. No direct download URL or filename is part of this RT1 contract.
