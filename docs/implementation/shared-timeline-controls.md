This amendment implements existing [AC-07](../design/browser-nes-platform.md#saves-rewind-and-controls), [D14](https://github.com/orgs/TuringTestee/projects/1) and [bug #236](https://github.com/TuringTestee/retro-coop/issues/236). Merge this plan before implementation.

## Reachable journeys and scope

- **Save, then load now:** public Host/Join → load NES through its visible chooser → Ready/Start → Save (Q) → advance → host Load (E) → controlling players accept → restored game resumes together. Surface Save and applicable Load with their keys in the existing Game menu; one action handler serves each button and shortcut. Guests can save locally, but only the host proposes a shared timeline change. Explain why Load is unavailable rather than silently ignoring it. Use the existing centered modal/focus treatment for confirmation and controller acceptance; keep the lobby, slots, game, settings and chat in their current containers.
- **Load later:** close/refresh, then use the same public Host path, choose the matching ROM and Load the compatible manual slot in the new lobby. Brief live reconnect retains current membership/timeline first. A refreshed host with an existing live lobby can reconnect and explicitly Load there; an expired lobby uses new membership/invitation. Automatic recovery does not overwrite or silently select Q's manual save. Missing/incompatible state, missing ROM and denied storage keep ordinary host/join/play available with actionable feedback. No hidden local mode is required.
- **D14 remains complete scope:** shared rewind up to the approved ten seconds and reset use the same transaction below; decline/timeout/concurrency/epoch requirements apply to all three operations. Current solo `Rewind`/`loadSave` APIs and orphaned panels do not deliver the public shared paths. Save/Load #236 is the first vertical implementation; it must not close D14 or claim a clean 1.0 while rewind/reset remain unimplemented. The existing D14 card owns those remaining journeys and the integrated gate; do not create a parallel backlog or defer them by implication.

## Owners and saved state

`GameSession` owns transaction authority and phase; `Rooms` binds current membership, selected game and controller revision. `GameClient` owns input fencing and checkpoint transfers. `LocalPlayer`/worker/native codec own atomic capture, candidate validation and import. `saves.ts` remains the sole IndexedDB owner. Extend these owners and remove replaced local-only shared-route guards/duplicate handlers; do not add another restore protocol beside them.

Q captures bytes, compatible identity, completed frame and hash in one worker operation, using the existing atomic capture foundation; update manual slots with existing compare-and-swap and local-data generation guards. Storage failure retains the prior save and current game. Validate current slot/selection/generation again before proposing and committing a load. Metadata is not authority: validate identity, bounded size, codec content and actual candidate state/hash against the exact ROM/core/settings. Existing byte-only slots/imports remain usable: derive validated metadata through the native codec; if their original scheduler frame is absent, explicitly establish a new timeline origin while retaining the exact saved machine state, never assert power-on freshness or invent a saved frame. Keep backup import/export compatible and automatic recovery distinct.

## One coordinated replacement transaction

1. **Freeze and propose.** Host binds one request to lobby, host membership, controller revision, old epoch, selected fingerprint and operation. Reuse the completed pause barrier to capture prior frame F/hash and a rollback snapshot before changing any machine. Stage the requested load/rewind/reset in an isolated native candidate. Reset follows the approved common battery/settings policy, not each browser's unrelated local battery. Rewind stages a valid retained target within the approved ten-second/32 MiB bound without consuming current history. Invalid candidate fails with the old timeline intact.
2. **Consent.** After the completed freeze, give each other current controller the proposed operation and truthful saved time/rewind amount. Require explicit acceptance within the approved 15 seconds. Observers do not gate consent; a host playing alone needs only their confirmation. Decline, host cancel, timeout, changed membership/roles/fingerprint or disconnection aborts, cancels staged work and leaves the exact previous F/hash paused. Do not silently accept a new controller or restart the timer for repeated requests.
3. **Stage every controller.** Reuse bounded ROM-free checkpoint transport, exact identity/digest/frame/hash verification and cancellable native prepare. Allocate a fresh candidate epoch; retain the old timeline and rollback snapshots until replacement is acknowledged. No machine runs the candidate and no old inputs can reach it. Concurrent role changes, another timeline request and game selection are rejected through this same transaction owner.
4. **Commit and acknowledge.** Only after every required controller is prepared and authority is rechecked may the coordinator authorize commit. Verify each native commit's candidate hash/frame before declaring the new shared timeline. If an import/ack fails or authorization changes, restore retained prior snapshots on reachable controllers, keep the authoritative prior timeline paused, and synchronize any returning participant from that prior state before resuming. Do not treat a sent commit or a partial import as success. If the host/lobby cannot recover, follow existing closure/reconnect rules and retain manual saves; never run a partially replaced game.
5. **Resume.** After all controller acknowledgments, use the existing shared start/resume barrier under the new epoch. Clear old scheduled inputs, held buttons, hashes, future history, audio queues and transfers. Discard stale packets and stale transaction completions by membership/revision/epoch/generation. Fence observers from old presentation/input and synchronize them to the committed checkpoint before observation resumes; they do not hold controller commit open. Discard rollback state only after acceptance is committed. Failed requests never change controller ownership.

Extend the existing staged checkpoint API to keep validated candidates and rollback state across the coordinated commit decision; its current prepare+immediate commit helper alone cannot provide this guarantee. Keep automatic capture from publishing a provisional replacement as recovered progress. The unused-lobby `gameRestore` initialization remains available for host recovery and later manual loading; removing its unused-timeline guard is not an active-game restore implementation.
