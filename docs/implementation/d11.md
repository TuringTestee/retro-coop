## Behavior and failure coverage

After an initial failure, each player explicitly retries; either retry order works and background inspection cannot renew canceled intent. The initial barrier requires exact file prerequisites, both live hashes, both acknowledgements, active play intent and a current authenticated peer epoch. A reservation is not established merely because the file or transport matches. A receiver is installed before offering readiness; known prepared epochs admit a bounded number of early packets while the other client’s Start notification is delayed.

The worker executes one admitted frame at a time. Shared scheduling follows an absolute wall-time target, retaining debt through input waits instead of discarding elapsed time at each RAF. It never predicts or skips emulated frames. The existing one-second stall bound also covers pause-drain checks when packets stop completely. State hashes are exchanged every 120 committed frames; omitted or repeated ordered checkpoints fail closed, including repeats after a completed comparison.

Pause identifies its requester, drains neutral input to one agreed boundary, and compares both resulting states. Both players explicitly acknowledge readiness; only the host can resume, using a new epoch and another acknowledged barrier. Unresolved focus or device loss prevents readiness. Chat focus releases game buttons while gameplay continues. A canceled guest releases the host’s shared guard, leaving a paused local game that the host can explicitly resume.

The shared screen places canvas/controls beside players, connection state and chat; session setup is disclosed separately, and All sessions can reveal the directory. Narrow screens stack these regions. Readiness text names the missing participant. Optional microphone capture remains off until the user enables it.
