## Deployment shape

1. Build the versioned client, coordinator and edge Docker targets for `linux/arm64` from one clean main commit. Publish immutable image digests to a dedicated ECR repository and record the source commit, image digests, asset manifest and emulator hash together. Build a coturn image or install coturn in the same Compose bundle. Keep one coordinator: rooms and temporary ROMs live on this instance and must not be split across machines.
2. Create a Docker-on-AL2023 Elastic Beanstalk **SingleInstance** environment with one `t4g.micro` Graviton ARM64 EC2 instance, fixed capacity one, and the Elastic IP that EB manages for it. There is no ALB or second EC2 machine. AWS documents [one instance plus an Elastic IP and no load balancer](https://docs.aws.amazon.com/elasticbeanstalk/latest/dg/using-features-managing-env-types.html) and [Docker Compose's container-owned proxy](https://docs.aws.amazon.com/elasticbeanstalk/latest/dg/create_deploy_docker.container.console.html). Allow only public TCP 80/443 for web and bounded UDP 3478 and relay ports for TURN; no SSH or public coordinator port. Route 53 has one exact A record for `retro-coop.1001.page` pointing to the current EB-managed Elastic IP. After any EB replacement or rebuild, re-read its sole instance and Elastic IP, reconcile that one DNS record if the IP changed, then verify HTTPS and TURN before reporting recovery. A single instance can be unavailable during replacement or deployment; record that expected recovery path rather than claiming high availability.
3. Run Caddy, the existing rate-limiting Nginx edge, the Node coordinator and coturn on that one host through Docker Compose. Caddy binds 80/443, obtains and renews a publicly trusted ACME certificate after DNS publication, redirects HTTP to HTTPS, and proxies only to Nginx on loopback. Keep its writable certificate storage across ordinary deployments; verify certificate reissuance and recovery after instance replacement. Nginx serves immutable client files and proxies same-origin WebSocket and authorized ROM upload/download to `127.0.0.1:8787`. Bind the coordinator and Nginx to loopback only. Coturn binds the EB Elastic IP's public UDP path and advertises that address. Verify EB health, container startup, WebSocket, ACME renewal/reissue, 1 GiB memory headroom and local/remote UDP reachability before accepting this shape.
4. The public TCP peer address at Caddy is the admission identity. Discard client-supplied forwarding headers there, pass exactly that peer address to loopback Nginx, and have Nginx overwrite the header to the coordinator with that value. Keep `COORDINATOR_TRUSTED_PROXIES=127.0.0.1` and prove forged headers, IPv4/IPv6 and distinct clients. The original [proxy boundary](d24-proxy.md) remains the security contract, adapted to the two same-host proxy hops.
5. Set `COORDINATOR_STAGE=staging`, exact `COORDINATOR_ORIGINS=https://retro-coop.1001.page`, the two included empty offers, required custom ROM upload, a bounded temporary ROM directory, and content-free logs. Uploads remain temporary while a room exists. Store the TURN signing secret in AWS Secrets Manager, scoped to this EB instance and its Compose services, never in images, source, command output or browser variables.
6. Coturn on the same instance serves UDP 3478 and a small relay port range, with time-limited credentials, allocation and bandwidth caps. Its public address is the EB-managed Elastic IP; verify that the IP and web/relay DNS continue to identify the new instance after an EB replacement. Prove direct and forced-relay play from independent networks; Relay only must fail visibly if TURN is unavailable instead of falling back to direct.

## Monthly cost and operating limits

[Elastic Beanstalk has no extra service fee](https://aws.amazon.com/elasticbeanstalk/pricing/); EC2, public IPv4, storage and transfer are billed. A current AWS Pricing API lookup on 2026-09-24 returned `t4g.micro` $0.0084/hour in `us-east-1`, below `t3a.micro` $0.0094/hour and `t3.micro` $0.0104/hour. Use one `t4g.micro`, the lowest-priced micro in this comparison. [Elastic Beanstalk supports Graviton on AL2023](https://docs.aws.amazon.com/elasticbeanstalk/latest/relnotes/release-2023-10-19-al2023.html). Build and test ARM64 images and prove startup plus bounded room/upload/relay load within its [1 GiB memory](https://aws.amazon.com/ec2/instance-types/general-purpose/) before public DNS; do not silently resize. At 744 hours, the instance is about $6.25, its one billed [public IPv4 address](https://aws.amazon.com/vpc/pricing/) about $3.72, and 28 GiB of gp3 EBS about $2.24: a $12.21 baseline before ECR/S3, logs, DNS, scheduled guard and transfer. The existing Route 53 zone adds no new zone fee for one record. Internet egress is variable; model it at the published list rate without assuming credits or a shared free tier. Recheck actual address count, volume sizes and rates before provisioning.

Before provisioning, record a 31-day scenario including EC2, EBS, public IPv4, ECR/S3, logs, DNS, scheduled guard and egress against the user-approved $50 actual-spend warning and $100 forecast shutdown trigger. Enforce the app's room/connection limits, edge response rate and global connection bound, a total upload request/size limit, and TURN allocations and bandwidth. Create an account-wide monthly AWS Budget with $50 actual-spend warning and $100 actual/forecast alerts delivered to the operator. Account-wide scope includes unrelated AWS costs, so it may shut this site down early; it avoids omitting unallocated public traffic from a tag-filtered budget. Verify the operator's alert subscription.

For a website that stays up after this session, deploy a dedicated EventBridge Scheduler task that invokes a small Lambda every six hours. The function reads only the named account Budget and, if actual or forecast monthly spend reaches $100, idempotently removes the exact website DNS A record and terminates only the named EB environment and its single instance. Scope its IAM role to those resources, log the action without room or user content, and alert the operator on guard failures. Keep the existing operator shutdown script as a manual fallback; the operator also checks spend and forecast daily. Include Scheduler, Lambda and logs in the worksheet. Test below/above-threshold and wrong-resource cases locally, invoke the cloud function in non-destructive dry-run mode, and verify the schedule is enabled before publishing public DNS. AWS reporting delay and publicly billed traffic still mean this is not a hard cap; record the accepted residual risk and actual charges plainly. Do not announce a public beta until D21/D22 validation is complete.

## Decision if the first package cannot be deployed

Do not silently substitute an HTTP-only environment, a shared coordinator behind multiple instances, untrusted forwarding headers, a second machine, or a relay-free public claim. Revise the exact affected architecture and review it before provisioning.
