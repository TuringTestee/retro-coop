The [minimal room journey implementation](minimal-room-journey.md) supersedes any assigned-controller-only **initial Start** check. All occupied members gate the first Start; only assigned controller owners gate subsequent gameplay frames. Later observer acquisition remains independent.

## Membership and transport

The coordinator owns exactly five stable slot IDs, each with availability, configured game role, optional member, and revision. A member owns a session, opaque membership identity, join intent, acquisition state, fingerprint/readiness, reconnect deadline, and download lease. Room host identity is separate from slot/controller role. Derive views, directory occupancy, admission, chat recipients, and operator reporting from this one collection.

Perform join, removal, closure, role swap, and reconnect mutations atomically. Commands identify room, affected slot/member, and expected revision; reject stale membership or authorization before side effects. Unique controller ownership is a validated invariant. Repeated requests are idempotent only for the same accepted operation. Closing an occupied slot fails; removal keeps the established explicit confirmation. Do not encode participant identity as `host|guest` or derive authorization from nickname. Host leave/timeout retains the existing room-close policy.

Generalize ROM download authorization and leases per membership. Existing temporary upload storage remains room-owned; removing one member cancels only their transfer. Included games retain verified catalog acquisition. Observers need matching ROM/core/settings too. Allow independent acquisition/retry after Start, without restarting the room or another browser's worker. Check metadata/frame byte limits against the complete five-member view rather than silently truncating it.

Use at most ten authenticated WebRTC pairs for five-member voice. Each pair has member IDs, pair ID, epoch, deterministic offerer, privacy policy, retry state, and signaling quotas. Game data travels only over the four host-member edges. Reuse each such connection for voice and separately labeled game/checkpoint channels; guest-to-guest connections carry voice only. Maintain one microphone capture with multiple senders and per-peer playback. A pair retry removes only that peer's media/transport state. Muting remains one explicit local choice across all senders, independent of focus, role change, or observer synchronization.

Apply existing relay-only policy to every pair before gathering candidates. Capacity accounting must count actual active pairs/relay allocations; the old one-pair-per-room estimate is invalid. Retain configured room/session limits unless measured five-member costs require a separately reviewed adjustment. Bound signaling and media resources by five members and ten pairs; dispose removed-member pairs promptly.

## One authoritative local timeline

The host runs the authority emulator even when assigned observer. Capability metadata defines available controller inputs; the current NES adapter exposes P1/P2. Each epoch carries the committed controller-to-member mapping and its revision. Unassigned controllers contribute neutral input. Existing shared-P1 mode remains a controller configuration with one owner, not duplicate member authority.

Assigned members submit delayed input to the host with epoch, revision, frame, and mask. Authenticate the sender against the current mapping; reject duplicates, stale inputs, and inputs outside the existing bounded scheduling window. Host-local input follows the same path. The host waits only for assigned owners, advances exactly one known-input frame, then broadcasts that committed frame's canonical controller vector. Replicas execute only those committed vectors; they cannot legitimately run ahead of the host. Preserve bounded input delay and missing-input pause/recovery. Hash checks from active players detect divergence; observer delay or mismatch triggers only that observer's resynchronization.

`LocalPlayer` must distinguish input-owning players from passive replicas. Observer execution, including the host in observer role, must not require a connected gamepad or canvas focus. Presentation and catch-up scheduling remain bounded; voice continues independently. A disconnected active owner pauses authority without discarding the last completed state; a disconnected observer does not enter any gameplay barrier.

## Checkpoints and role transactions

Reuse `spikes/d02/src/local_state.rs` and its ROM-free canonical `RCSTATE1` codec, rather than the old NROM-only experimental checkpoint format. Its compatibility identity covers ROM/core/settings/schema; it validates digest, shape, allocation geometry, and mapper state before restore. The current shared local-file limit is 2 MiB. Preserve these checks for untrusted peer bytes. Audit and extend the codec for any currently supported game profile lacking checkpoint support before claiming this feature complete; do not reduce admitted game compatibility to avoid that obligation.

Add explicit peer-checkpoint operations to the worker boundary. Capture bytes, canonical state hash, and frame at one completed frame boundary. Import only an authorized current transfer; set worker and scheduler frame/epoch together, discard old queued audio and rewind history, and release held inputs. Existing `state-import` does not restore the worker's JavaScript frame counter and cannot alone implement this protocol. Preserve the prior valid local state on validation/import failure and retain progress on all cancelled operations.

Use one transfer per recipient, at most four outgoing transfers, and no more than 2 MiB assembled bytes each. Bind transfer metadata to membership, gameplay epoch, frame, identity, byte count, and digest. Use chunks no larger than 12 KiB with checked offsets over a dedicated ordered checkpoint channel; cap each sender's queued bytes at 256 KiB and resume on actual buffer drain. Reject unsolicited, duplicate, gapped, oversized, or stale chunks. Retain a compact ring of at most 2,048 committed input records and 64 KiB for catch-up, plus only bounded current checkpoint/transfer buffers. Set a 15-second transfer deadline and a 15-second catch-up deadline. Treat these as initial measured implementation limits: a change must preserve finite bounds and prove supported five-member workloads, rather than mask failure with unlimited retention or retries.

For an observer joining or recovering, export frame F, continue host play, and retain input records after F. The observer imports F and replays those records locally with catch-up audio discarded, then enters normal presentation. Ring overflow, timeout, or mismatch cancels only that attempt and offers a fresh synchronization. No observer readiness, download, hash report, or transport buffer can block active players. Rate-limit/coalesce checkpoint requests and share immutable export bytes where possible so four observers cannot multiply capture work without bound.

Before first Start, role changes update the validated assignment directly; a fresh-start barrier compares matching initial state hashes without requiring a committed-frame checkpoint at power-on. Once a timeline exists, the coordinator records each role change as a pending transaction against the current membership/assignment revision. The host first stops dispatching new frames. If no known-input worker frame is in flight, freeze immediately at the existing last completed frame F, including when a departed owner has exhausted the input queue and advancement is already stalled. If a known-input frame was already dispatched, await only that bounded worker operation and freeze at its completed boundary; a worker timeout fails the transaction visibly without publishing new roles. Never require another input packet or a future frame to reach the freeze boundary. Capture F and its canonical state hash, release held input, and discard every uncommitted queued input. Synchronize the proposed active controller owners to F using the same checkpoint path. Validate their readiness hashes; removed owners and observers are not required to acknowledge. Only then atomically commit the slot roles, mapping revision, and new epoch. Seed neutral input for the negotiated delay and resume the same machine state. Existing observers receive the new epoch and resynchronize if necessary without gating commit.

A failed transaction leaves the previous committed mapping and exact game state at F intact and paused. Retry repeats synchronization; cancel preserves the old assignment and resumes only if its owners are ready. Membership changes invalidate the pending transaction before publication. The host may replace a departed owner through a fresh transaction. This mechanism also covers joining an open controller slot after Start and reconnecting an active owner; no fresh-game reset is an acceptable shortcut.
