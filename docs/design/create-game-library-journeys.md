Create Game lets a player pick one verified NES game, choose who can see the room, and create it. The browser library shortens repeat hosting without putting file controls in the public room list.

Audience: Human

# Create Game journeys

Based on [direction](create-game-library-direction.md) and the approved [room transfer journey](room-rom-transfer.md).

| Journey | Entry → decisions and actions → feedback → outcome | Recovery |
| --- | --- | --- |
| J1 Join a public room | Open Retro Coop → scan/search Public rooms → choose Standard/Relay-only beside Join → choose one available row's **Join** or **Join as host** for an empty bundled offer → room preparation → guest **Prepare to play** or host **Start game** → shared/solo play. | Stale directory shows Retry; a full/playing row has no Join; failed guest acquisition offers Retry or Return. Create controls never interrupt this route. |
| J2 Host a saved game | Public rooms → **Create game** → inspect recent preview and Your games → select one saved or bundled entry → rehash and load exact bytes in host browser → choose Public/Unlisted and Standard/Relay-only → **Create room** → creation/upload progress → waiting room → Start alone or after guest prepared. | Missing/corrupt bytes or failed local load deselect the entry and offer **Add NES file**; failed upload offers Retry with the same selected bytes or Cancel to Create Game. |
| J3 Host a new file | Public rooms → **Create game** → **Add NES file** or drop on this page → validation and local load result, selected name/size → choose access and connection policy → **Create room** → upload progress → waiting room → Start. | Invalid or unloadable file leaves selection unchanged with an inline reason; quota denial says “Available in this tab only”; cancelled/failed upload returns to selected Create Game state without a public ghost room. |
| J4 Reuse a guest download | Join a host-shared room → exact verified download → browser saves by hash → leave room → **Create game** → the downloaded title appears once in Your games → select it and **Create room** → host upload of that saved copy. | Storage denial leaves the current tab playable and explains it will be absent next visit; a deleted/evicted copy disappears or becomes unavailable and can be added again. |
| J5 Manage local games | Settings → Local data → inspect Downloaded games → delete one or clear all with confirmation → Create Game reflects removal while current loaded play stays in memory. | Cancel confirmation leaves the list; deletion failure preserves the row and reports the error. |
| J6 Leave setup | Public rooms → **Create game** → **Back to rooms** before publishing. | Any validated selection remains available in this tab; no room or upload is left behind. Browser Back follows the same route. |
| J7 Close and reopen Guest place | Host enters waiting room with Guest place **Open** → while empty choose **Close place** → room stays listed with **Guest place closed** and no Join → host chooses **Open place** → Join returns. | If another guest joined just before Close, keep place occupied and show that guest; host may remove that guest first. Failed mutation leaves the previous status and offers Retry. |
| J8 Remove an occupying guest | Host sees occupied Guest place in waiting room → **Remove guest** → inline confirmation in the slot area → confirm → guest is disconnected and Guest place becomes Open → host may Close it. | Cancel restores the occupied row. Failed removal keeps the guest row and states the error. Guest sees the room closure/removal reason and can return to Public rooms. |
| J9 Join or inspect a closed room | Guest sees a public waiting row with **Guest place closed** and no Join, or opens an unlisted invite to that room → reads the same status → returns to Public rooms. | When host reopens the place, the current directory/invite view updates to Join; stale Join receives a visible full/closed result without entering preparation. |
| J10 Use secondary pages without covered content | Player enters Settings, Local data, Saves, Rewind or Game help through the one control for that task → the page replaces the current content in the same app frame → acts or reads → **Back** returns to the invoking page with focus restored. | Destructive choices show inline confirmation in the page's action area; cancel preserves state. Errors appear in that page. While playing, room status sits beside/below the canvas without covering it. |

At each setup state, selection is the next action until a game is selected; then **Create room** is the single primary forward action. Public/Unlisted changes the room's visibility but does not create it. Settings and Local data remain secondary tasks.

The Guest place is a host control only before Start. Closing an empty place changes admission, not the room's public visibility or capacity. During play, admission is already closed by the existing no-late-join rule. Fixed page regions may stack and scroll at narrow widths; no control floats above another region.
